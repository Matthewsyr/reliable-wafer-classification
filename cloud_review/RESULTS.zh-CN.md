# 晶圆复检成本与未标注覆盖

原 Colab 笔记本在 Google 托管 CPU 上完成，运行编号 `20261102T042635Z_bf1507`。本次衔接工作读取了已保存的执行输出，在 Snowsight 中独立核算了汇总成本，并对固定复检名单改变损失倍率。计算单位是模拟损失单位。

## 同一候选池上的复检决策

校准使用 11,307 张开发调参晶圆。成本评价使用此前已查看过的 11,591 张开发审计晶圆。固定上游模型为种子 42 的 RF71，校准后的任意缺陷概率达到 0.5 即入池。三种模型使用相同的 3,642 张模拟报警候选，来自 903 个批次。按预先规定的批次排列生成 1,000、1,000、1,000、642 张的四个队列，名额分别为 200、200、200、128。候选中有 3,484 张真实缺陷和 158 张正常片。80 张真实划痕中有 62 张入池，另有 18 张在排序前就被排除。

原协议将普通缺陷的漏检损失定为 1，正常片为 0。每次复检耗费 0.1，按假设平均避免被检缺陷损失的 90%。三个情景分别使用等损失、Scratch 五倍损失、Near-full 五倍损失。按标签结算成本。固定队列与训练种子仅用于回顾模拟，缺少实际生产日期、真实损失和人工处置标签。

| Scratch 五倍损失，固定满额复检 | 种子 42 | 种子 123 | 种子 2026 |
|---|---:|---:|---:|
| RF71 成本／千张候选 | 833.169 | 830.203 | 831.439 |
| 几何 RF77 成本／千张候选 | 814.388 | 813.893 | 815.376 |
| RF77 节省／千张候选 | 18.781 | 16.310 | 16.063 |
| 计入未入池漏检后的节省／千张全来料 | 5.901 | 5.125 | 5.047 |
| RF77 多占用名额的真实划痕净数 | 3 | 2 | 2 |
| RF77 少占用名额的正常晶圆数 | 64 | 58 | 57 |

RF77 在这个情景下同时换入了更多划痕和其他真缺陷。按批次对固定名单差值重抽样的条件性 95% 区间分别为 [1.225, 39.414]、[1.255, 32.729]、[0.111, 31.598] 单位／千张候选。三个模型种子复用同一批样本。原 Colab 在等损失或 Near-full 五倍情景下重新排序时，两种 RF 的成本点估计相同。

## Snowflake 验证

连接查询使用现有浏览器登录，`CURRENT_ROLE()` 和 `CURRENT_WAREHOUSE()` 返回当前会话上下文。`01_validate_colab_summary.sql` 由真实逐类计数重建成本，三组与已保存结果一致。`02_fixed_list_sensitivity.sql` 固定原来在划痕五倍情景下挑出的两套名单，将划痕损失改为 0、1、2、5、10 倍，得到 15 条通过参照核对的记录。该计算回答名单已经确定后，收益对价格误设的敏感程度。重新改变排名应使用原概率和新评分规则。

种子 42 还做了逐片核验。云端导出的 `06_seed42_wafer_replay.sql` 包含同一批 3,642 张候选、队列和容量、批次、真实标签、RF71/RF77 的正常与划痕分数，以及原浮点点积和冻结名单参照。Snowflake 在各队列内用 `ROW_NUMBER()` 重新排名。按原点积处理数值近似的同分项后，两个模型各选 728 张，和冻结名单的差异均为零。339 张进入 RF77 名单，另有 339 张退出。RF71 和 RF77 的成本分别为 833.168588688 和 814.387699066 单位／千张候选，差为 18.780889621。

直接用代数等价的两个概率计算收益并排序时，RF77 有 62 张的入选标记与归档不同，两个算法的收益分数最大舍入差为 `8.88e-16`。本种子两种排序都复检到 56 张真实划痕，总成本也相同。逐片身份复现应固定数值算法和同分规则。第一次 SQL 的名单核对也一致，但先对定点数取平均再乘 1,000，导致成本核对的 `1e-7` 容差检查失败。最终版本先累加成本再以双精度除以样本数，在同一容差下通过。两次原始返回表均已保留。

## 正常训练样本未覆盖的尺寸

按晶圆的原始高和宽精确匹配，开发审计集有 **3,181 张**晶圆的尺寸在训练正常片中从未出现。其中 643 张是正常片、53 张是真实划痕、2,485 张是其他缺陷。固定的 RF71 上游报警规则将 643 张正常片中的 **152 张**送入候选池，误报率为 **23.64%**。其余尺寸的 7,348 张正常片仅有 6 张报警（0.08%）。这一层集中了全部 158 张正常误报中的 96.2%。这里的报警指模型判定可能存在任意缺陷，不能据此统计有多少正常片被明确分成 Scratch。[开发审计分层计数](results/shift/audit_cost_strata.csv)

两种模型重排同一批候选，总名额均为 728。下表只统计上述 3,181 张，每格三个数依次对应种子 42、123、2026。

| 零正常尺寸覆盖层 | RF71 | RF77 |
|---|---:|---:|
| 实际入选模拟复检的正常片（共 152 张报警） | 82 / 75 / 76 | 19 / 18 / 20 |
| 实际入选模拟复检的真实划痕（共 53 张，50 张报警） | 46 / 47 / 47 | 47 / 47 / 46 |
| 已报警、未获复检的缺陷数 | 1,988 / 1,997 / 1,994 | 2,003 / 2,001 / 2,005 |
| 这些未获复检缺陷的模拟漏损（相对单位） | 2,004 / 2,009 / 2,006 | 2,015 / 2,013 / 2,021 |
| 本层总模拟成本（相对单位） | 2,164.6 / 2,167.5 / 2,165.2 | 2,166.7 / 2,165.0 / 2,172.0 |

RF77 在这一层少复检了 63 / 57 / 56 张正常片，复检到的真实划痕相差 +1 / 0 / −1 张。还有 3 张真实划痕在上游就没有报警，两种排序都接触不到。本层共有 2,523 张已报警的真缺陷，即使把全体 728 个名额都给这一层，仍至少有 1,795 张无法复检。因此，全体候选的模拟成本下降可以与局部漏损上升同时发生。表中的片数来自真实开发标签和冻结的模拟名单。损失与总成本采用本报告的假设，普通缺陷漏损为 1、划痕为 5、每次复检费为 0.1，处置可避免 90% 的缺陷损失，单位不对应美元。[成本收据](results/shift/cost_receipt.json)

## 未标注数据的用途

Colab 核对原文件后扫描了全部 811,457 张晶圆，包括 638,507 张未标注、54,355 张开发和 118,595 张原测试晶圆。用原始批次或完全相同的像素哈希逐跳连接后，共有 34,610 个组件。含有任何有标签晶圆的 8,848 个组件整体排除，涉及 153,525 张未标注晶圆。合格的未标注记录有 484,982 张，同图只保留最小原始行号，得到 **434,498 张唯一候选图，来自 25,762 个组件**。此前只排除直接同批或同图时得到 465,745 张，多跳隔离又排除了 31,247 张。候选行号、原尺寸、批次、组件和像素哈希已保存在云端，公开收据记录了清单的校验值。[池统计](results/shift/pool_summary.json) · [清单收据](results/shift/pool_receipt.json)

这批候选图覆盖了上述 3,181 张开发审计晶圆中 **2,455 张（77.18%）**的尺寸，另有 726 张的尺寸仍找不到。此前记录的 78,154 / 78,158 用的是直接隔离的旧池，分母是原测试集中尺寸未在全部开发正常片出现过的正常晶圆。两个数字对应不同人群与候选池。尺寸相同只能说明有图可用，候选的缺陷标签仍然未知。本轮诊断完成了隔离和成本核算，没有训练自监督模型或生成伪标签。要确认预训练是否同时减少正常误报、保住划痕召回，还缺一组独立批次的真实标签。任何单种子试验都应另列为探索结果。[尺寸覆盖与漏损](results/shift/pool_support_and_cost.csv) · [实验决策记录](results/shift/decision.json)
