## 开组前需要现场提供什么

1. **负责人、范围和时间。** 指定单一工厂、产线和产品范围，登记未来起始时刻、30 天窗口、MES 全量导出责任人、标注经费和角色。开组前把登记文件的 SHA-256 在独立留档位置签收。团队在关账前保持模型、阈值、入组和抽样规则不变。没有满足条件的现场输入时，状态保持“等待新批次”。
2. **连续、完整的来片清单。** 私有 `arrivals.csv` 列顺序为 `wafer_id,lot,arrival_utc,map_file`，每片一次，时间带时区，包含未报警来片。图像采用原始有序高宽的数值 `.npy` 二维图，0 背景、1 通过、2 失效。图路径相对于单独的图目录。MES 另给同一时间窗的独立到片总数，须与清单一致。缺图、缺 lot、缺时间或缺整批记录时暂停出包，由数据负责人核对。保留原始签收、截止时间、完整性证明和原文件哈希。
3. **历史暴露登记册。** 所有曾用于训练、校准、选模、自监督或阅片的数据均进入保护范围。现有项目保守地保护全部 811,457 张 WM-811K 图，包括未入自监督抽样的图。后续接触过的外部数据也应加入。现场负责统一物理晶圆、真实 lot 与来源 ID 的命名空间，建立跨系统别名映射并核对原图编码。不能说明映射和采集时间时，独立性无法确认。
4. **两名互相独立的盲审人员和一名仲裁人员。** 熟悉 WM-811K 九类定义。无法可靠归类的案例应记录并请求补充专家材料。缺失案例保持待核状态，完整标签到齐前不发布主结算。记录各次阅片协议、操作者代号和时间，业务执行中已有的报警片处置记录另外保留。
5. **单独的验证资源。** A 和 B 是两个互斥的影子运行方案，各方案遵守每千报警片 200 名额。验证工作要标注两者的并集，再审未入选片和未报警片。研究用人力须单独落实，按入样病例安排双读，并为争议预留第三读。这些验证病例不计入 A 或 B 的模拟检查费。登记时写入所能审查的最大病例数 `--budget`。如抽样后超预算，程序在发放盲图或接收真值前停止。需要改变核验设计时重新登记新的未来窗口。

## 入组、隔离与盲法怎样执行

保护册逐图记录真实 lot、稳定 ID，以及“原始高宽的小端 int64 表示 + 连续 uint8 像素”的 SHA-256。开组程序验证新图并连接其 lot 与相同图像哈希。任何组件中只要发现与历史 ID、lot 或原图哈希的交集，就将整个新组件隔离。跨多个新 lot 的间接连接同样传播。结果同时报告 MES 来片总数、被隔离数和进入主结算的全来片分母。常见的相同正常图也可能触发保守隔离，应在读出时披露覆盖范围。核验范围限于可观测的身份、批次与原图重复，设备和工艺的未知相关性仍然存在。

在合格人群中，以 `真实 lot × 处置分层` 抽样。两者都选、仅 A、仅 B 三层概率为 1。未报警层以及“已报警、两者都未选”层分别等概率无放回抽 10%，向上取整，每个非空层至少 2 片，只有 1 片时全标。私有台账保存每片的纳入概率 `pi = 已抽数 / 层总数`。抽样使用在到片前登记的私有随机密钥，与标签无关。保留两者都选的样本用于估计绝对成本，策略边际差异由两者独选名单决定。

只把 `blind/` 的匿名编号和同名原图分别发给两名读图人员。图以统一数值编码重新写出，不带路径、批次、模型分数、是否报警、处置分层、排序或对方意见。保管人保留 `private_ledger.csv` 和 `enrollment.json`，对外签收 enrollment 收据的哈希后才接收标签。仲裁人只接收有争议的匿名案例，独立给出最终类标。保留发放包和交回文件的哈希，以核查所读图像及解盲顺序。

## 如何结算和决定

每个策略分别报告四部分相对损失。①上游未报警缺陷。②报警但未获名额的缺陷。③送检后仍存在的 10% 残余漏损。④实际拟议复检张数 × 0.1。前两项各自拆为 Scratch 和全部其他缺陷的漏掉数。把总成本除以全部合格到片数再乘 1,000。盲标抽查项使用 Horvitz–Thompson 权重 1 / π，检查张数和费用直接使用冻结名单全数。结果中的漏检数是总体估计，可出现小数。

程序给出两方案的绝对成本、有限现场样本的分层抽查标准误及 B−A 的配对区间。并集全标使这批片中两方案的**成本差**不受未抽中共同处置样本的影响。95% 区间以相同图像相连的整组 lot 为单位配对重抽 2,000 次，固定本次队列及模型。至少 30 个独立组件才作方向判断。这是报告下限，招募前仍需根据可接受的业务差异与预期批次量评估精度。区间全低于 0 时支持 B，全高于 0 时支持 A，跨过 0 或样本不足时保留“不确定”。Scratch 及其他缺陷漏检数用来解释结果。真实工厂成本、复检检出率与处置成效需要现场采集，在可用前统一写为“成本情景模拟”。

## 执行命令

在仓库根目录运行。建历史册使用已有额度的托管 CPU 及原始已校验的 Kaggle 文件。新产线图像和私有注册材料只在现场批准的计算与存储环境中使用。依赖为 Python 3.10+、NumPy、joblib、scikit-learn 1.6.1，建册还需要 pandas 和 psutil。权重使用 07 私有证据输入包的 `inputs/` 目录。下例变量由现场负责人填写。

```sh
CODE=cloud_review/blind_review_08
python "$CODE/build_registry.py" --raw "$WM811K_PKL" --out prior08
# 如还存在其他曾接触的来源，在上方命令添加 --extra other_exposures.csv
python "$CODE/prospective.py" register --registry prior08 --site "$SITE_LINE_SCOPE" \
  --start "$FUTURE_START_WITH_OFFSET" --budget "$AUDIT_CASE_BUDGET" --out registration08

# 窗口关闭、完整清单核对后，使用开组前签收的登记文件 SHA
python "$CODE/prospective.py" enroll --plan registration08/registration.json \
  --plan-sha "$SIGNED_PLAN_SHA" --registry prior08 --arrivals arrivals.csv \
  --maps "$ORIGINAL_MAPS" --models "$FROZEN_MODELS" --mes-count "$SIGNED_MES_COUNT" --out enrollment08

# 两份读图文件列均为 case_id,label。仲裁文件只含意见不一致的全部案例
python "$CODE/prospective.py" settle --enrollment enrollment08 --enrollment-sha "$SIGNED_ENROLLMENT_SHA" \
  --reader1 reader1.csv --reader2 reader2.csv --adjudication resolved.csv --out results08
python "$CODE/synthetic_check.py"
# 私有权重已准备时，额外在合成晶圆图上联调真实 RF71 初筛和 RF77 输出
python "$CODE/synthetic_check.py" --models "$FROZEN_MODELS"
```

没有分歧时可以省略 `--adjudication`。所有输出目录必须是新目录。注册密钥、原图、逐片记录、专家文件和两个真实检查点留在私有存储。现在能运行的真实数据活动限于已有历史数据登记与回放。新研究的注册、入组、阅片和成本结算等待现场材料。
